# Android delivery roadmap: TWA first, offline APK later

Статус: **TWA first view собран 2026-07-13; ожидается проверка на Pixel 9a**.
Первой Android-версией является sideload TWA поверх существующей PWA;
браузерная PWA остаётся без изменений. Автономный APK с упакованной игрой —
вторая фаза, после стабилизации Android-визуала и gameplay.

## Фаза 1 — TWA как основной Android-контур

- TWA открывает текущий `https://www.farklepit.ru/` в trusted fullscreen: это
  тот же live web-клиент, который мы развиваем и деплоим сейчас.
- В Android wrapper явно настраиваем sticky immersive и display-cutout mode, а
  не рассчитываем на DOM-кнопку `requestFullscreen()`. Цель: fullscreen ещё до
  первого web-кадра, без browser chrome и без PWA-кнопки «На весь экран».
- Требуются release keystore, package id `ru.farklepit.game` и
  `/.well-known/assetlinks.json`. Play Store не требуется, но Digital Asset
  Links требуется и для sideload: без него браузер покажет Custom Tab toolbar.
- Первый APK нужно собрать и установить один раз. Последующие изменения
  TypeScript/CSS/ассетов публикуются обычным web deploy и подхватываются TWA
  как сайтом; **новый APK для них не нужен**. Сборка нового APK нужна только
  при изменении native wrapper: иконки, splash, signing, package/config,
  minSdk или TWA display-mode.
- Обновление web-клиента внутри TWA следует текущей политике service worker:
  после web deploy игра обновляется через обычное обновление/перезапуск, а не
  через переустановку APK.
- Проверки на Pixel 9a: холодный старт, вырез камеры, landscape, звук, вход в
  матч, web-обновление без нового APK и fallback при временно сломанном
  `assetlinks.json`.

## Фаза 2 — самостоятельный APK (offline-first)

- Это отдельное решение после TWA. APK запускается без сети, заполняет экран
  Pixel включая область выреза камеры с первого кадра и не требует PWA-кнопки
  «На весь экран».
- Внутрь пакета попадает воспроизводимая сборка `dice-client/dist`: shell,
  JS/CSS, шрифты, модели, текстуры, menu/UI dice и звуки, нужные для локальной
  игры. Список ассетов проверяется build-скриптом, а не собирается вручную.
- Онлайн-лобби и мультиплеер остаются дополнительным сетевым режимом. Они
  используют текущий production backend, когда сеть доступна.
- Офлайн-режим означает настоящую локальную партию, а не закэшированный экран.
  Текущий authoritative матч зависит от `/ws`, поэтому для него нужен отдельный
  local-match путь без соединения с сервером: локальная физика, бросок, выбор,
  подсчёт очков и бот/одиночная игра. Синхронизацию серверной физики и scorer
  при этом сохраняем как инвариант.

### Архитектура офлайн-версии

1. Отделить новый Android-проект от TWA wrapper, либо заменить его только после
   того, как TWA доказал Android UX. В git храним исходники и скрипты сборки,
   но не keystore и не готовые APK.
2. После `npm run build` копировать `dice-client/dist` в Android assets и
   открывать его через `WebViewAssetLoader` на HTTPS-подобном app-assets origin,
   а не через `file://`. Это даёт локальную поставку файлов без небезопасных
   file-доступов.
3. В нативном Activity включить edge-to-edge immersive и режим display cutout до
   создания WebView; системные панели скрывать штатным Android API. Именно
   native слой, а не DOM `requestFullscreen()`, отвечает за отсутствие полосы и
   не требует центральной кнопки.
4. WebView не получает лишних разрешений и file access. До реализации отдельно
   проверить CSP, CORS, Origin для `/ws` и `/auth`: локальный app-assets origin
   может отличаться от production origin, поэтому сетевой мультиплеер нельзя
   считать совместимым без этой проверки.
5. PWA остаётся браузерным способом установки и разработки. Её service worker
   не является механизмом офлайн-игры внутри APK: APK имеет свой упакованный
   baseline. При необходимости web-кэш будет только оптимизацией, а не
   источником истины.

### Сборка и обновления офлайн-версии

1. Создать постоянный release keystore вне git и сделать резервную копию: даже
   для sideload обновлений следующий APK обязан быть подписан тем же ключом.
2. Собрать signed APK, установить его на Pixel 9a через ADB и проверять upgrade
   поверх предыдущей версии; каждый релиз повышает `versionCode`.
3. Изменение упакованного клиента требует нового APK. Обычный web deploy не
   заменяет файлы, уже лежащие в приложении — это сознательная цена честного
   офлайна. Сетевой backend, если режим включён, обновляется отдельно.
4. Play Store остаётся вне scope. TWA и автономный APK — разные варианты
   доставки: второй не обязан сохранять Digital Asset Links, если больше не
   открывает удалённый сайт как trusted activity.
